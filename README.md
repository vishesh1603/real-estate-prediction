# Real Estate Prediction

Three ML tasks built around a residential real estate business: will a customer buy,
what should a property cost, and will a proposed scheme succeed. Each task has a
baseline notebook and an optimized notebook that loads the baseline's saved model and
only replaces it if a new technique actually beats it. Results are served through a
multipage Streamlit app.

## The Three Tasks

| Task | Data | Target(s) |
| --- | --- | --- |
| Price Prediction | `real_estate_user_cleaned.csv` / `cleaned_listings.csv` | Property price (regression) |
| Purchase Intent | `cleaned_users.csv` | Purchase probability + value (regression), High/Medium/Low intent (classification) |
| Scheme Success | `historical_scheme_data.csv` | Leads/bookings/conversion/success score (regression), demand level (classification) |

Full details on features, targets, and what was excluded to avoid leakage are in
`data/data_dictionary.md`.

## Results

| Task | Baseline | Optimized | Verdict |
| --- | --- | --- | --- |
| Price (regression) | R²=0.821 | R²=0.854 | Improved, new model in use |
| Purchase Intent (regression) | avg R²=0.650 | avg R²=0.670 | Improved, new model in use |
| Purchase Intent (classification) | macro-F1=0.746 | macro-F1=0.734 | No improvement, baseline kept |
| Scheme Success (regression) | avg R²=0.733 | R²=0.669 | No improvement, baseline kept |
| Scheme Success (classification) | macro-F1=0.787 | macro-F1=0.779 | No improvement, baseline kept |

Two of five genuinely improved. The other three are reported as negative results
rather than forced wins. The scheme success dataset is small, and the Medium category
in purchase intent overlaps with its neighbors rather than being underrepresented.

## How to Run

```
pip install -r requirements.txt
```

Run each baseline notebook before its optimized counterpart. The optimized notebooks
load the baseline's saved model as the model to beat:

```
jupyter nbconvert --to notebook --execute --inplace "notebooks/Model Devolopment/price_prediction_model.ipynb"
jupyter nbconvert --to notebook --execute --inplace "notebooks/Model Devolopment/price_prediction_model_optimized.ipynb"

jupyter nbconvert --to notebook --execute --inplace "notebooks/Model Devolopment/purchase_intent_model.ipynb"
jupyter nbconvert --to notebook --execute --inplace "notebooks/Model Devolopment/purchase_intent_model_optimized.ipynb"

jupyter nbconvert --to notebook --execute --inplace "notebooks/Model Devolopment/scheme_success_model.ipynb"
jupyter nbconvert --to notebook --execute --inplace "notebooks/Model Devolopment/scheme_success_model_optimized.ipynb"
```

Then launch the dashboard:

```
streamlit run Home.py
```

`Home.py` routes to the five pages under `pages/`: Price Prediction, Purchase Intent,
Scheme Success, Insights, and About. Each page loads whichever saved model won for its
task, so the optimized price and purchase-intent-regression models are used, along
with the baseline purchase-intent-classification and scheme-success models.

## Notes

- `scikit-learn>=1.3` is required for `sklearn.preprocessing.TargetEncoder`, used in
the optimized price notebook.
- `imbalanced-learn` is required for `SMOTE`, used in the optimized purchase-intent
notebook.
- Neither optimized notebook overwrites the baseline's saved model unless it actually
wins on a held-out test set. Model selection in the baseline notebooks uses
`GridSearchCV`; the optimized notebooks add cross-validation-based selection,
`TargetEncoder`, permutation importance, quantile regression (price), SMOTE with
probability calibration (purchase intent), and repeated cross-validation with learning
curves (scheme success) to check whether the small dataset is the real bottleneck.
- `old_app.py_backup/app.py` is the single-file version of the dashboard that predates
the `Home.py` + `pages/` multipage layout. It is kept for reference and is not used by
the current app.
