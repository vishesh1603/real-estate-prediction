# Real Estate Prediction

Three ML tasks built around a residential real estate business: will a customer buy,
what should a property cost, and will a proposed scheme succeed. Each task has a
baseline notebook and an optimized notebook that loads the baseline's saved model and
only replaces it if a new technique actually beats it.

## Project Structure

```
real-estate-prediction/
├── data/
│   ├── raw/
│   │   └── historical_scheme_data.csv        scheme-level data (real inputs + outcomes)

│       ├── cleaned_listings.csv               cleaned property listings
│       └── cleaned_users.csv                  cleaned customer survey data

│   ├── price_prediction_model.ipynb           baseline
```

## The Three Tasks

| Task | Data | Target(s) |
|---|---|---|
| Price Prediction | `cleaned_listings.csv` | Property price (regression) |
| Purchase Intent | `cleaned_users.csv` | Purchase probability + value (regression), High/Medium/Low intent (classification) |
| Scheme Success | `historical_scheme_data.csv` | Leads/bookings/conversion/success score (regression), demand level (classification) |

Full details on features, targets, and what was excluded to avoid leakage are in
[`docs/documentation.md`](docs/documentation.md).

## Results

| Task | Baseline | Optimized | Verdict |
|---|---|---|---|
| Price (regression) | R²=0.821 | **R²=0.854** | Improved — new model in use |
| Purchase Intent (regression) | avg R²=0.650 | **avg R²=0.670** | Improved — new model in use |
| Purchase Intent (classification) | macro-F1=0.746 | macro-F1=0.734 | No improvement — baseline kept |
| Scheme Success (regression) | avg R²=0.733 | R²=0.669 | No improvement — baseline kept |
| Scheme Success (classification) | macro-F1=0.787 | macro-F1=0.779 | No improvement — baseline kept |

Two of five genuinely improved. The other three are reported as negative results
rather than forced wins — see `docs/documentation.md` for why (small dataset for
scheme success, class overlap rather than imbalance for purchase intent's Medium
category).

## How to Run

```bash
python -m venv venv
venv\Scripts\Activate.ps1      # Windows
# source venv/bin/activate     # macOS/Linux

pip install -r requirements.txt
```

Run each baseline notebook before its optimized counterpart — the optimized notebooks
load the baseline's saved model as the model to beat:

```bash
jupyter nbconvert --to notebook --execute --inplace notebooks/price_prediction_model.ipynb
jupyter nbconvert --to notebook --execute --inplace notebooks/price_prediction_model_optimized.ipynb

jupyter nbconvert --to notebook --execute --inplace notebooks/purchase_intent_model.ipynb
jupyter nbconvert --to notebook --execute --inplace notebooks/purchase_intent_model_optimized.ipynb

jupyter nbconvert --to notebook --execute --inplace notebooks/scheme_success_model.ipynb
jupyter nbconvert --to notebook --execute --inplace notebooks/scheme_success_model_optimized.ipynb
```

Then launch the dashboard:

```bash
streamlit run app/app.py
```

The app automatically uses whichever model won for each task — the optimized price
and purchase-intent-regression models, the baseline purchase-intent-classification and
scheme-success models.

## Notes

- `scikit-learn>=1.3` is required for `sklearn.preprocessing.TargetEncoder`, used in
  the optimized price notebook.
- `imbalanced-learn` is required for `SMOTE`, used in the optimized purchase-intent
  notebook.
- Neither optimized notebook overwrites the baseline's saved model unless it actually
  wins on a held-out test set — model selection in the baseline notebooks uses
  `GridSearchCV`; the optimized notebooks add cross-validation-based selection,
  `TargetEncoder`, permutation importance, quantile regression (price), SMOTE +
  probability calibration (purchase intent), and repeated cross-validation + learning
  curves (scheme success) to diagnose whether the small dataset is the real bottleneck.
